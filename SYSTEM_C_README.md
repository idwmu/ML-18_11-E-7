## 6. What Member D Needs From This API

| Field | Type | Description |
|---|---|---|
| `trip_id` | str | Echoed from request |
| `predicted_arc_ids` | list[int] | Ordered arc IDs — 0-based row indices into the trip's `.arcs` file |
| `points` | list[[lon, lat]] | GPS observations in temporal order (degrees) |
| `n_gps_points` | int | Total GPS observations processed |
| `n_route_arcs` | int | Length of predicted route |
| `candidate_miss_rate` | float | Quality indicator [0.0, 1.0]; lower is better |
| `model_name` | str | Which model was used |

**Note for Member D:** `arc_id` values are **per-trip positional indices**, not global IDs. To draw the route geometry, look up each `arc_id` in the trip's `.arcs` file to get `(from_node, to_node)`, then look up node coordinates in the trip's `.nodes` file.

API base URL: `http://<Laptop1-IP>:8000`  
Swagger docs: `http://<Laptop1-IP>:8000/docs`

## 7. Fedora Deployment Guide

### Step 1 — Activate the virtual environment

```bash
source .venv/bin/activate
```

### Step 2 — Install dependencies

```bash
pip install -r requirements.txt
```

### Step 3 — Run unit tests

```bash
pytest tests/ -v
```

Expected: **33 tests passed**.

### Step 4 — Start the FastAPI server

```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

The server listens on all network interfaces at port 8000.  
`--reload` enables hot-reload for development. Remove it for production.

### Step 5 — Test the health endpoint (new terminal)

```bash
curl http://localhost:8000/health
```

Expected response:

```json
{"status": "ok", "model_name": "DummyModel-v0", "version": "0.1.0"}
```

### Step 6 — Test POST /predict

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"trip_id": "00000001"}'
```

Expected: a JSON response with `predicted_arc_ids`, `points`, and `n_gps_points`.

### Step 7 — View Swagger UI

Open in your browser:

```
http://localhost:8000/docs
```

You can test both endpoints interactively from the Swagger page.

## 9. Fedora Firewall Configuration (port 8000)

If Member D cannot reach the API from Laptop 2, run these commands **on Laptop 1**:

```bash
# Check the active firewalld zone
firewall-cmd --get-active-zones

# Open port 8000 in the active zone (usually 'FedoraWorkstation' or 'public')
sudo firewall-cmd --zone=FedoraWorkstation --add-port=8000/tcp --permanent

# Reload firewall rules
sudo firewall-cmd --reload

# Verify
firewall-cmd --zone=FedoraWorkstation --list-ports
```

## 12. Known Limitations (Stub vs. Final)

| Limitation | Impact | Fix when |
|---|---|---|
| Stub uses Haversine to arc **midpoint**, not exact perpendicular segment distance | Candidates are approximate; some correct arcs may be missed | Replace `_load_trip_data()` when Member A's pipeline is integrated |
| `bearing_difference`, `segment_length`, `speed`, `heading`, `arc_degree` features are 0 in stub | Model sees only distance; DummyModel ignores all features anyway | Integrate Member A's feature pipeline |
| `DummyModel` is deterministic and not trained | Prediction quality is low; for demo only | Set `PATHSNAP_MODEL_PATH` when Member B provides model |
| No authentication on API endpoints | Anyone on the LAN can send requests | Acceptable for hackathon scope |
| `--reload` in uvicorn command | Should not be used in production | Remove `--reload` for final demo |
